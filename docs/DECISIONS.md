  `pnpm-workspace.yaml` (`allowBuilds`): Prisma and SWC only.
- **Turborepo 2.11** runs `build`, `lint`, `typecheck`, `test`, `test:integration`, `test:e2e`

- **TypeScript 6.0.3**, not 7: typescript-eslint supports TypeScript below 6.1. Strict mode,

- **ESLint 9.39.5**, not 10: `eslint-plugin-react` (pulled in by `eslint-config-next`) does not

- **Prisma 7.10.1**, not 8: npm's `latest` tag points at 8.0 release candidates. Prisma prints a

- **Vitest 5** with SWC for decorator metadata. Coverage thresholds: `packages/shared` 95%, API
  and other server packages 80%. Integration tests (`*.int.test.ts`) need real Postgres and

### Repository layout

### API and worker

- Fastify adapter. `/healthz` and `/readyz` are served at the root for probes; every other route
  lives under `/api`.
- `/readyz` checks Postgres (`SELECT 1`) and Redis (`PING`) concurrently with a 2 s timeout each.
  The public response only says up or down plus latency; failure details are logged, never
  returned. It answers 503 when anything is down and is never cached.
- Requests carry an id: a well-formed incoming `x-request-id` (8–128 safe characters) is reused,
  otherwise a UUID is generated. It is echoed in the response and present in every log line.
- Exactly one trusted proxy hop (Caddy), so the apps see the real client IP from
  `X-Forwarded-For`. Body limit 1 MiB in the api, 2 MB at Caddy.
- Logging is pino JSON with credentials and secrets redacted and query strings stripped (they can
  contain phone numbers). Successful health probes are silenced at response time, because
  Fastify's middleware layer rewrites `req.url` before pino-http's start-of-request filter runs.
- The worker publishes a heartbeat key `smsvio:worker:heartbeat:<hostname>` in Redis with a TTL
  of three intervals. Its container health check reads that key.
- Sentry (`@sentry/nestjs`) loads through `node --import ./dist/instrument.js` and is disabled
  without `SENTRY_DSN`. User info, cookies, bodies, query strings and most headers are excluded.
  Browser-side Sentry for the web app is deferred until there is client logic worth monitoring.

### Web

  shadcn's `cn` class-merging package), lucide icons, next-themes.

  requests reach the browser.
- `output: 'standalone'`; the same server bundle runs in Playwright, Docker and production.
- Libraries named in the spec but not used yet (TanStack Query and Table, Recharts, cmdk, form
  libraries) are installed in the phase that first needs them.

### Containers and hosting

- One multi-stage `Dockerfile` with targets `api`, `worker`, `web` and `migrate`, all built from
  a single build stage; `pnpm deploy --prod` produces a pruned bundle per service. Runtime base:
  `node:26.13.0-trixie-slim`, user `node`. `docker-bake.hcl` builds all five images in one run.
- The migration image contains only the Prisma CLI, the schema and the migrations.
- Caddy is a custom image (`infra/caddy`) with the Caddyfile baked in, running as uid 10001. The
  binary's file capability is removed and the container binds ports 80/443 through the
  namespaced sysctl `net.ipv4.ip_unprivileged_port_start=0`, so it works with all capabilities
  dropped and `no-new-privileges`. The admin API is off; a health listener answers on
  `127.0.0.1:8081` inside the container.
- App containers run with a read-only root filesystem, `cap_drop: ALL`, `no-new-privileges`,
  `init`, memory limits and health checks. Only Caddy publishes ports (Docker-published ports
  bypass UFW, so nothing else may publish).
- Postgres 18.6 and Redis 8.10.3 sit on an internal network without internet access. Redis uses
  AOF persistence and `noeviction`, which BullMQ queues will require.
- HSTS is one year without `includeSubDomains` or `preload`, because future subdomain use is not
  decided.
- Only `linux/amd64` images are built; the VPS is x86-64 with 2 vCPU and 8 GB RAM, so the
  bootstrap's swap file (only for ≤ 4 GB RAM) was not created.

- CI runs on pull requests and on `main`: lint, typecheck, unit tests with coverage thresholds,

## Phase 1 — Accounts and shell (2026-11-11)

### Inputs the spec asks for, and what was done instead

Spec section 16 asks for an SMTP host, port, username, password, from-address, and a platform
admin email before Phase 1. None were provided. They are environment variables, not committed
secrets. Local Compose sends mail through Mailpit (`axllent/mailpit:v1.27`) with no
authentication. Production Compose requires `PUBLIC_ORIGIN` and `APP_ENCRYPTION_KEY`. SMTP
settings are required only when `EMAIL_MODE=smtp`. `SEED_ADMIN_EMAIL` is optional. The migrate
container refuses `SEED_ADMIN_PASSWORD=smsvio-demo-local` when
`NODE_ENV=production`. The local migrate service sets `NODE_ENV=development` because the image
itself sets `NODE_ENV=production`.

### Accounts

- Sessions are 256-bit tokens stored as SHA-256. The cookie `smsvio_session` is httpOnly.
  `smsvio_csrf` is readable by the page (double submit). `smsvio_org` is httpOnly. All are
  `SameSite=Lax`, path `/`, and `Secure` only when `PUBLIC_ORIGIN` is https. The session lasts
  30 days and slides when fewer than 29 days remain. `lastSeenAt` updates at most every 5 minutes.
- Cookie-authenticated mutations require a matching `Origin` and `x-csrf-token`. Sign-up,
  sign-in, and password reset require `Origin` only. A resource that belongs to another
  organization returns 404. A role that is too weak on the caller's own organization returns 403.
- Passwords use argon2id at the OWASP minimum (`memoryCost` 19456, `timeCost` 2,
  `parallelism` 1), shared as `ARGON2ID_OPTIONS`. Sign-in of an unknown email still hashes a
  dummy password. Sign-up of an existing email returns the same "check your email" message.
- TOTP uses `otpauth` with a window of one step (30 seconds). The pending secret is encrypted
  until the user confirms a code. A code reuses a step only if its counter is greater than
  `totpLastStep`. QR codes are data URLs, so the content security policy allows `img-src data:`.
- Secrets at rest use AES-256-GCM. The stored form is `v1.<iv>.<tag>.<data>` (base64url) and the
  key is `APP_ENCRYPTION_KEY` (64 hex characters). Replacing the key does not re-encrypt old rows.
- Rate limits live in `RATE_LIMITS` and use a Redis sorted-set window under `smsvio:rl:`.
  Responses are 429 with `Retry-After`. Emails in Redis keys are SHA-256, not the raw address.
- Phone verification cannot send SMS until Phase 3. The one-time code is emailed to the verified
  address, and the settings page says so. Numbers are checked with an E.164 regular expression;
  libphonenumber arrives in Phase 2. Audit metadata stores a masked number. Five wrong attempts
  invalidate the code.
- New organizations are `PENDING_VERIFICATION`. Suspension does not block sign-in in this phase.
  The banner links to Settings → Business. The sidebar only links to pages that exist: Overview,
  Users, Settings, and `mailto:support@smsvio.com`.
- The demo user is a platform admin and the owner of "SMSVIO Demo", so the dashboard works
  before the admin console (Phase 6). The seed is idempotent: it sets the password only when it
  creates the user, and it creates an organization only when that user has no memberships.
- `AuthToken` is an extra table (not drawn in spec section 8) for verification, reset, and phone
  codes. `dailySpendCapMicros` stays null until Phase 3. `messageRetentionDays` defaults to 365.
  `smartEncoding` defaults to true and has no UI yet.
- Deleting an organization writes the audit row with `organizationId` null, then deletes the
  organization. An organization-scoped audit row would be removed by `ON DELETE CASCADE`.
- Internal errors are `{ code, message, fields? }`. Unknown routes still return Nest's
  `{ statusCode: 404 }` so the Phase 0 health tests stay valid. `ApiErrorFilter` is registered
  after `SentryGlobalFilter` in `configureApp`: Nest reverses global filters and uses the first
  match, and the Sentry filter matches every error.
- `@tanstack/react-table` is installed but unused. Its v9 legacy API is deprecated, and the lint
  rule treats deprecation as an error, so Users is a plain HTML table with server-side paging.
  The command palette and toasts are custom. `cmdk` and `sonner` inject style tags that the nonce
  content security policy rejects. `style-src-attr 'unsafe-inline'` stays, because Radix
  positions components with element style attributes. `script-src` and `style-src` stay nonce-only.
- The web app proxies `/api/*` to `API_INTERNAL_URL` with a route handler. Caddy already routes
  `/api` in Compose and production, so that handler is unused there and returns 404 when the
  variable is unset in production.
- Tenant isolation is tested against real Postgres in `apps/api/test/tenant-isolation.int.test.ts`.
  The unit suite uses an in-memory stand-in and does not count as integration coverage.
- `pnpm-workspace.yaml` `allowBuilds` now also includes `argon2` and `esbuild` (argon2 hashes
  passwords; esbuild is required by `react-email`). Do not run `pnpm approve` for the TanStack
  agent-skills notice.

## Google sign-in and optional email (2026-11-11)

- `EMAIL_MODE` is `disabled` or `smtp`, default `disabled`. The API boots with no SMTP settings
  when email is disabled. `smtp` requires `SMTP_HOST` and `SMTP_FROM` and keeps the existing
  verification, reset, and invitation mail. Switching mode does not require a code change.
- When email is disabled, `/signup` shows Google only and a short note that email registration
  is coming soon. `/signin` keeps the password form so existing passwords and the reset-link
  command still work, and hides "Forgot your password?". Invitations return a one-time link to
  the inviter instead of sending mail. Phone verification is hidden and the API refuses it until
  SMS exists in Phase 3.
- Google's browser redirect lands on `/auth/google/callback` (not under `/api`). Caddy sends
  that path to the API. `pnpm dev` and Playwright proxy it the same way.
- Google uses the authorization-code flow with PKCE (S256), `state`, and `nonce`. The ID token
  is checked for issuer, audience, expiry, and nonce, and `email_verified` must be boolean true.
  `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are both set or both empty. Empty hides the
  button and the API still boots. Test-only endpoint overrides are ignored when
  `NODE_ENV=production`.
- A new Google user is email-verified, has no password, and names an organization on the
  overview page. A verified account with the same email is linked and keeps its password and
  sessions. An unverified account is linked, marked verified, its password is cleared, and its
  sessions are revoked. A Google-only user sets a password later under Settings → Profile.
  TOTP, when enabled, is still required after Google sign-in.
- The platform admin is the account whose verified email equals `SEED_ADMIN_EMAIL`, whichever
  way that person signs in. The flag is applied at sign-in, not only by the seed. When
  `SEED_ADMIN_PASSWORD` is empty, migrate does not create a password user.
- `users.passwordHash` is nullable. `users.googleSub` stores the Google subject.
- The password-reset command prints the link to stdout for the operator. Tokens, links, and
  codes are not written to application logs. Request logs already drop the query string, and
  `set-cookie` stays redacted.

### Where the quality gates run (2026-11-11)

This machine does not have Docker and does not run a local stack. Before a phase is reported
complete, lint, typecheck, unit tests, and `pnpm build` run here. Playwright, the Postgres
integration tests, and the fresh-clone Compose smoke test run in GitHub Actions on every push
to `main` and must pass there. The deploy job does not start unless all three succeed.

## Phase 2 — SMS library, contacts, templates, lookup (2026-11-11)

- The SMS library lives in `@smsvio/shared`. The Next.js client imports encoding, templates, and
  CSV from the main barrel. `libphonenumber-js/max` and the time-zone table are only on
  `@smsvio/shared/phone`, which the API and the seed import. Account forms still check the
  E.164 shape with the existing regex so the browser bundle stays small. When email can be
  sent, `startPhone` also normalises the number with libphonenumber before it stores it. While
  `EMAIL_MODE=disabled` the existing `403 phone_unavailable` response still returns first.
- Time zones come from the Apache-2.0 libphonenumber `map_data.txt`, vendored as
  `packages/shared/src/sms/timezone-prefixes.ts`. The longest matching prefix wins. The region
  is the city of that zone when exactly one zone matches, and null when several do.
- Seed data marks US and CA as alphanumeric-sender blocked and registration required, because
  those carriers do not accept alphanumeric sender ids. Every other country starts allowed and
  not requiring registration. The rows are initial data. `createMany` with `skipDuplicates`
  loads them and does not overwrite a later operator edit. Countries are seeded even when
  `SEED_ADMIN_PASSWORD` is empty.
- The sample gallery is the `TEMPLATE_GALLERY` constant, not a database table, so it does not
  depend on the demo seed. Copying a sample creates a draft.
- `AUTO_APPROVE_TEMPLATES` defaults to `false`, including in both Compose files, so a missing
  production variable leaves templates pending for the operator. `.env.example` and the
  Playwright API set it to `true`. Production `/opt/smsvio/.env` was not regenerated.
- `Message` exists now so contact history and template analytics are real queries. There is no
  send pipeline. `providerId`, `routeId`, and `apiKeyId` are optional ids without foreign keys,
  because those tables arrive with sending.
- Saving a pending or approved template returns it to `DRAFT` and clears the rejection note.
  Submit rejects `message_too_long`. A draft may keep a body that is over the segment cap.
  Only `APPROVED` templates are sendable, and sending itself is Phase 3.
- A CSV import returns the rows it rejected, including duplicates in the file or already stored.
  It does not skip them silently. Opt-out is shown and can be filtered. There is no toggle
  until keyword handling exists.
- Template analytics are an SVG bar chart. Recharts is not installed. The shell links only to
  pages that exist: Overview, Templates, Contacts, Users, Settings, Number lookup, and support
  mail.
- Number lookup is limited to 30 requests a minute per signed-in user. The key is
  `smsvio:rl:lookup:<userId>`.
- The editor's API tab shows cURL, Node, and Python for `POST /api/v1/messages`. That route is
  not implemented until the public API phase. The snippets are the request the editor is
  specified to show.

## Phase 3a — Routes, rates, senders, and the ledger (2026-11-11)

- Markup is per provider, not global. `Provider.markupPercent` is required. `Route.markupPercent`
  is an optional override for that destination. There is no platform markup and no minimum margin.
- The customer price per segment is the cost of the primary route times
  `(1 + effective markup / 100)`, rounded up to the nearest 100 micros (0.0001 USD). The effective
  markup is the route override when it is set, otherwise the provider's markup. Prices are computed
  when they are read, so a change to cost, priority, enabled, or either markup shows up on the next
  read. Computed prices are not stored as `Rate` rows.
- The primary route is the enabled route whose provider is `ACTIVE`, with the lowest priority
  number, then the highest weight, then the lowest id. A network-specific route beats a
  country-wide route. A disabled provider does not set the customer price. Each route row still
  shows its own formula price and margin, which can be negative.
- Price overrides, highest first: `OrgRate` (one customer), then a manual `Rate`, then the computed
  primary-route price. The latest `effectiveFrom` at or before now wins. CSV import inserts a newer
  manual rate and does not delete history. Duplicate destinations in one file are rejected.
- The customer is charged the quoted price even when a later failover uses a different provider.
  Each message will store `costMicros` of the route that was actually used, so margin can be
  negative. Charging and failover are Part B. The columns exist now.
- A new organization's `dailySpendCapMicros` stays null and inherits
  `PlatformSetting.defaultDailySpendCapMicros`, which starts at 20,000,000 micros (20 USD). An
  admin can change the platform value and can set or clear a per-organization override. The cap is
  not enforced until send exists.
- Ledger signs: `amountMicros` is the change to available balance, except `CHARGE`, which records
  the negative price and does not change available. `HOLD` decreases available and increases held.
  `RELEASE` does the opposite. `TOPUP`, `REFUND`, and `ADJUSTMENT` move available only. The nightly
  check is `available = SUM(amount)` excluding `CHARGE`, and held is the open remainder of
  `HOLD` / `RELEASE` / `CHARGE` grouped by `refId`. The same hold, charge, or release for one
  `refId` is a no-op. The worker runs that check once per UTC day (`smsvio:ledger:sweep:YYYY-MM-DD`)
  and logs differences at error. There is no operator alert channel yet, and there is no BullMQ
  queue in this part.
- An admin balance adjustment requires a reason of 3–500 characters, is written to the audit log
  in the same transaction, and cannot be zero. The maximum is 1,000,000 USD.
- Someone who is not a platform admin gets 404 on `/api/internal/admin`, not 403.
- `MockProvider` never contacts a network. Delivery is decided by the last four digits of the
  destination: 1001 delivered, 1002 undelivered, 1003 permanent failure, 1004 expired, 1005 slow
  delivered (30s), 1006 temporary failure, anything else delivered. The callback signature is the
  SHA-256 hex of the secret. The seed provider has no secret, so verification fails closed. SMPP
  and HTTP health checks return not-ok and do not open a connection.
- The seed creates provider `mock` at 50% markup and one country-wide route per country at priority
  100, weight 1, and 10,000 micros, without overwriting an existing provider markup or route. The
  resulting list price is 15,000 micros (0.0150 USD). The admin console labels that provider
  Simulated until Phase 7. The platform shared sender is a `platform_settings` value. The seed
  fills it with the fictional number 12025550199 only while the column is null, and leaves an
  empty value an operator saved. The same deploy inserts countries, dial codes, and a published
  set of mobile networks, skipping rows that already exist. `Route.mccmnc` is not a foreign key.
  A seed-admin user who already exists and has no membership receives one organization and the
  OWNER role. A refused demo password does not fail the migrate container after that reference
  data is written.
- Sender requests stay `PENDING`. The approval queue is Phase 6. Enabling a country is idempotent
  and uses the shared sender until then. `registrationComplete` is false when the country requires
  registration; completing it is Phase 6. Real phone verification stays deferred.
- `Message.providerId` and `Message.routeId` now reference Provider and Route and are set null if
  that row is removed. `apiKeyId` still has no foreign key.
- Part A is in production at `86d0846` ([CI run 43114439327](https://github.com/Murvanidz3/smsvio/actions/runs/43114439327)).
  `https://smsvio.com/readyz` returned ok after that deploy.
  `AUTO_APPROVE_TEMPLATES` was not changed. A trial concurrency group of one run per commit was
  reverted, so pushes to a branch still share one CI group.

## Phase 3b — Send pipeline (2026-11-12)

- The send pipeline uses Redis lists and sorted sets (`smsvio:q:sms.send`, `smsvio:q:sms.send:delay`,
  `smsvio:q:sms.dlr`). BullMQ is not a dependency. The API accepts a message and pushes its id.
  The worker sends. A 30 second lock plus a status claim keeps a duplicate queue entry from sending
  twice.
- Accept order follows the spec: role, organization status, idempotency key, phone, enabled country,
  registration, sender, opt-out, approved template, length, quote, 20 sends per second, daily spend
  cap, then one hold and a `QUEUED` row. The customer is charged the quoted price. `costMicros` is
  the route that accepted the message. A failed send releases the hold.
- Until real carriers exist, dispatch uses only `MOCK` providers whose status is `ACTIVE`.
  Opt-out is `Contact.optedOut`. The OptOut table and auto-replies stay in Phase 6. Every transition
  writes a `MessageEvent`. Webhook delivery stays in Phase 4. Delivery receipts arrive at
  `POST /api/hooks/providers/mock` and are queued on `sms.dlr`. A repeated receipt is the same
  sorted-set member, and a late `delivered` after `expired` is the one allowed correction. The Send
  Activity panel is a server-sent event stream and falls back to polling. An idempotency key is
  unique per organization for 24 hours. The organization send ceiling defaults to 20 per second and
  can be raised with `ORG_SENDS_PER_SECOND` for a local load test. Network (MCC/MNC) is not resolved;
  quotes use the country-wide route.
- `AUTO_APPROVE_TEMPLATES` stays `false` in the repository and in both Compose files. Production
  `/opt/smsvio/.env` sets it to `true` so Send is usable before the admin review queue exists. It
  returns to `false` when that queue ships in Phase 6.
- An organization that is not `ACTIVE` or `SUSPENDED` may send only to the signed-in user's verified
  account phone. The admin Organizations screen can set that organization to `ACTIVE`.
- Message validity is 72 hours. A temporary failure retries the same route three times, then the next
  route. A permanent failure moves on immediately. No remaining route fails the message with
  `no_route`. The in-memory burst used by the worker test is the double-charge proof. A ten-minute
  100-per-second run is not part of CI.
